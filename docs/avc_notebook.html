TP Noté — Prédire le Risque d'AVC¶

Un AVC (accident vasculaire cérébral) survient lorsque l'irrigation sanguine du cerveau est perturbée, soit par une obstruction, soit par une rupture de vaisseaux sanguins. Cela peut entraîner des séquelles graves, voire la mort, et chaque année, l'AVC tue environ 5 millions de personnes dans le monde.

Dans ce TP, nous allons travailler avec un jeu de données qui contient les informations médicales de 5 110 patients, avec 12 variables pour chaque individu. L'objectif est de prédire si un patient est à risque de faire un AVC, en se basant sur ces caractéristiques (la variable cible est "stroke", où 1 signifie un AVC, et 0 signifie qu'il n'y en a pas).

L'enjeu principal ici est de ne pas manquer un patient à risque. En effet, un "faux négatif" (c'est-à-dire prédire qu'un patient n'aura pas d'AVC alors qu'il est à risque) est beaucoup plus dangereux qu'un "faux positif" (prédire qu'un patient aura un AVC alors qu'il n'est pas à risque). Si un patient à risque est ignoré, cela peut mettre sa vie en danger. C'est pourquoi il est crucial d'opter pour des métriques qui tiennent compte de cette situation, et d'ajuster notre modèle pour minimiser ce type d'erreur.

Étape 2 — Préparation des données¶

Avant d'entraîner nos modèles, il est essentiel de préparer correctement les données. L'ordre des opérations est crucial pour éviter toute fuite de données:

  1. Supprimer la colonne id: Cette colonne n'apporte aucune information utile pour la prédiction.
  2. Faire le train/test split est effectué de manière stratifiée, ce qui signifie que la répartition des classes (AVC vs pas d'AVC) est conservée dans les deux ensembles.
  3. Imputer les NaN uniquement sur le train: Pour éviter la fuite de données, l'imputation des valeurs manquantes ne doit être effectuée que sur l'ensemble d'entraînement.
  4. Encoder les variables catégorielles: Transformer les variables catégorielles en variables numériques.
  5. Standardiser les variables numériques uniquement sur le train : Appliquer la standardisation (moyenne = 0, écart-type = 1) uniquement sur l'ensemble d'entraînement pour éviter de "trahir" l'ensemble de test.

3 — Résultats de la baseline triviale¶

Un modèle qui prédit systématiquement "pas d'AVC" obtient une accuracy de 95.11%, ce qui semble impressionnant. Cependant, ce modèle est totalement inutile :

  • F1-score : 0.0 → il ne détecte aucun AVC
  • Rappel : 0.0 → les 50 patients à risque sont tous manqués

Cela montre que l'accuracy ne reflète pas la véritable performance du modèle dans un contexte déséquilibré, où l'importance des faux négatifs (patients à risque manqués) est primordiale. Dans un cas médical comme celui-ci, manquer des patients à risque d'AVC est inacceptable.

C'est pourquoi, dans ce TP, nous utiliserons principalement des métriques comme le rappel et le F1-score pour évaluer les modèles.

Étape 6 — Ajustement du seuil de décision¶

Par défaut, les modèles utilisent un seuil de 0.5 pour décider si un patient est à risque d'AVC. Mais est-ce optimal dans notre contexte médical ?

En abaissant le seuil, on détecte plus d'AVC (rappel plus élevé) au prix de plus de faux positifs (précision plus faible). En contexte médical, cette décision est justifiée car manquer un AVC est bien plus grave que sur-alerter.

Étape 7 — Bonus : SMOTE¶

SMOTE (Synthetic Minority Over-sampling Technique) est une technique de sur-échantillonnage qui génère de nouveaux exemples artificiels pour la classe minoritaire (AVC=1).

Contrairement à class_weight='balanced', qui ajuste les poids des classes, SMOTE crée de nouvelles données synthétiques afin d'équilibrer les classes.

Il est important de noter que SMOTE est appliqué uniquement sur l'ensemble d'entraînement pour éviter toute fuite de données.

Conclusion générale¶

L'objectif de ce TP était de prédire le risque d'AVC à partir des données médicales de 5 110 patients.

Réponse à la question initiale : Oui, il est possible de prédire le risque d'AVC avec un rappel de 0.80, ce qui signifie que 80% des patients à risque sont détectés. Le modèle retenu est la Régression Logistique avec class_weight='balanced'.

Points clés : Le dataset présente un déséquilibre marqué (5% d'AVC), et l'accuracy seule est trompeuse. C’est pourquoi nous avons utilisé le rappel et le F1-score comme métriques principales. L'utilisation de class_weight='balanced' est essentielle pour détecter les AVC, et un seuil de 0.3 permet de détecter 42 AVC sur 50.

Limites du modèle : Le modèle présente certaines limites : il a une précision faible, générant de nombreux faux positifs. De plus, le dataset est relativement petit avec seulement 5 110 patients, et certaines variables importantes peuvent manquer.
